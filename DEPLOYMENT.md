# Розгортання та відновлення

Повна інструкція всього сервера: `../luxpower-automation/docs/server-restore.md`.
Клонуйте репозиторії поруч у `/home/maksym/projects/`; поточна інтеграція
використовує Python 3.13+, systemd і Codex CLI 0.167.2.

- Runtime — стандартна бібліотека Python; створіть нову `.venv` на новій ОС.
- На новій машині потрібний власний `codex login`. Автентифікація не входить у Git.
- `deploy/provision.py` готує приватну sandbox-політику та посилання на login.
- Для відновлення діалогів перенесіть узгоджену приватну копію
  `~/.local/share/codex-telegram/`, а не лише код.
- Бази користувачів містять діалоги, повідомлення й черги; не публікуйте їх.
- Незавершені staged-зміни лежать у `~/projects/codex-workspaces/`:
  збережіть їх окремо, перш ніж створювати робочі копії заново.
- Бот має запуститися першим і створити `state/codex-access.json`.
- Після завершення завдань код агента застосовується командою
  `systemctl --user restart codex-telegram-agent.service`.
- Зміна лише списків доступу не потребує перезапуску агента.
- Перезапуск не повторює завдання, що вже виконувалися. Файли могли бути
  частково змінені — перед повторним завданням перевірте результат.

Не послаблюйте sandbox-політику для обходу помилок перенесення шляхів.

## Поточні дозволи

Поточні дозволи: інтернет і LAN без списку доменів; реальні показники сервера,
стан/логи служб та керування користувацькими службами через `host_system`;
наявні розетки — через `device_control` без розкриття ключів. Для змін поза
проєктами або root — один погоджений пакет усіх пов'язаних дій. Прямі зміни
захищеного коду, секрети й канали самопогодження залишаються закритими.
Після оновлення політики та інструментів перезапустіть вільний агент і надішліть
`/new`, щоб новий діалог отримав додані інструменти. Робочі файли не стираються.


## Швидке оновлення на налаштованій Raspberry

Спочатку дочекайтеся завершення завдань Codex і погоджених root-команд.
Поточний runtime не потребує сторонніх Python-пакетів.

```bash
cd ~/projects/codex-telegram-agent
git pull --ff-only
.venv/bin/python deploy/provision.py
systemctl --user restart codex-telegram-agent.service
systemctl --user --no-pager status codex-telegram-agent.service
```

Потім у Telegram надішліть `/new`, якщо оновлення додає інструменти.
Це новий контекст розмови; файли проєктів не видаляються.
`deploy/provision.py` застосовує політику доступів, зберігає наявні project trust
налаштування й не перезаписує існуючі робочі копії.
Сам `git pull` не застосовує новий sandbox-конфіг і не перезапускає процес.
